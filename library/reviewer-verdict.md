# The independent reviewer: what a read is

Scope: every repository under this rulebook, in either stack. Open when: judging whether a commit is cleared, or how a verdict is signed and why no comment counts.

**A review clears only the commit it read.** A later push voids it: a round's fixes land as one push and the CTO asks once, and a repository's check goes green only when the reviewer has read the current commit — by itself, with no hand re-run. The verdict is a check run, whose commit and conclusion are fields GitHub fills rather than sentences to be parsed. This repository goes further, because here the proposer may not clear its own addition: its gate opens only on a read with no blocking finding, so a head the reviewer left a blocking finding on stays red until the push that answers it, and an advisory finding stays standing on the pull request. A report to the Chairman names the commit that was reviewed.

**The verdict is derived, never given** (decision 0014): the read returns findings, each blocking or advisory, and the workflow makes the verdict, any blocking first. Prose decides nothing; a missing, malformed, unknown-severity or cut-off answer clears nothing.

**Why a check run and never a comment** (settled on [#34](https://github.com/Adonis80/how-we-build/pull/34); [#38](https://github.com/Adonis80/how-we-build/pull/38) failed it). A read must arrive **under a login a branch cannot wear, as a signal a branch cannot erase**. A comment by `github-actions[bot]` is neither: every workflow token in the repository wears that login, a throwaway branch's included, and anyone with write access can edit or delete an issue comment — the very population a review gate defends against. **Only a GitHub App can create a check run**, and nobody with write access can forge, edit or delete one. So the reviewer signs as the App `juku-reviewer` (created on the Chairman's account 19 September 2026), and its verdict is that check run's own `conclusion` on its own `head_sha`. The comment the workflow also posts is the same words where people can read them, and the gate reads none of it. A GitHub App is free; the managed alternative costs a Team plan and $15–25 a review, and does not let the model or the effort be chosen, which is the Chairman's ruling broken at the moment of purchase.

**The door, and why it is proved rather than stated.** The App's private key is what a branch would need to sign with, so it lives in a repository **environment** named `reviewer` whose deployment branch policy admits `main` alone, and the reviewer workflow's job names that environment: a run whose ref is a branch is refused the job before it starts. The reviewer reaches `main` because it triggers on `issue_comment` alone, whose run's ref is the default branch (proved on #38, run `35343442166`, `head_branch: main`). Documentation is not this standard: `.github/workflows/door.yml` is a standing, re-runnable proof — push a branch named `proof/door-*` and watch the job refused, or run it on `main` and watch it read the key. A green door run on a branch means the badge is forgeable and nothing should merge until the policy is back.
