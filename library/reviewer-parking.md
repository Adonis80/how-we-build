# The independent reviewer: parking

Scope: every repository under this rulebook, in either stack. Open when: about to park a slice, or the reviewer seems out.

**Ask, then park on the answer.** A session may park a slice only on a refusal it was given itself, on that pull request, in that hour — never on a note, a roadmap line, a handover or another session's report saying the reviewer is out. One ask settles it in seconds, and the refusal it earns is the park's evidence; a session that stops for a reason that is not real is woken by nothing, because nothing happens. Learned 21 September 2026 from two Hemz OS slices (P47, P34) that parked on a secondhand belief while the reviewer was answering in seconds; the story is on those pull requests.

**When the gate can count no read** — the reviewer unreachable, its allowance spent or the service down — the gate does not open and is not waived. One reviewer means one read, and no read means no green. The slice parks: one comment on the pull request names the blocker, then no further pushes and no further asks, which only deepen the hole. Nothing watches for the reviewer's return, on any clock: a watch cannot see it, since only an ask can tell and a parked slice makes none. The return is found by the next session to start, whose ask on the first parked pull request — the oldest, or first in a repository's own order where it sets one, as this one's does (`library/changing-the-rulebook-merge.md`) — either lands or is refused. Parked work never stops the line: the next item is taken up by this session where *Session changeover*'s continuation test passes, otherwise from `main` in a fresh one, which reads the open pull requests first rather than rebuilding the parked slice (`library/carries-sessions.md`). When the reviewer returns, parked pull requests re-enter review in that same order, one ask each. Beyond the Reviewer-down issue, none of this reaches the Chairman: a parked slice is the CTO's wait, not his problem, and he hears of it only when it moves something he was promised.

**When a rollout breaks the reviewer** (6 October 2026; first canary: run 37538877446). After a machinery merge, `.github/workflows/canary.yml` sends one tiny real read; red, it opens the Reviewer-down issue and `check.sh` holds every machinery pull request till a canary passes; `.github/workflows/monitor.yml` opens it for an ask no read follows. The change is reverted unless a smaller repair is shown safer. **The emergency route**, for reviewer repair or revert only: an admin merges with GitHub's own bypass; the pull request links the outage issue and the exact repair SHA and names the check bypassed; it is recorded as an emergency exception, never a clean review; and a canary runs after it lands.
