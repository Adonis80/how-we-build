# The independent reviewer: parking

Scope: every repository under this rulebook, in either stack. Open when: about to park a slice, or the reviewer seems out.

**Ask, then park on the answer.** A session parks a slice only on a refusal it was given itself, on that pull request, that hour; never on a note, a roadmap line or another session's report that the reviewer is out. One ask settles it in seconds.

**When the gate can count no read** (the reviewer unreachable, its allowance spent, the service down), the gate does not open and is not waived. The slice parks: one comment names the blocker, then no further pushes or asks. Nothing watches for the reviewer's return, on any clock; the next session to start asks on the oldest parked pull request (or first in the repository's own order) and finds out. Parked work never stops the line: the next item is taken. When the reviewer returns, parked pull requests re-enter review in order, one ask each. Beyond the Reviewer-down issue, he hears of it only when it moves something he was promised.

**When a rollout breaks the reviewer.** After a machinery merge, `.github/workflows/canary.yml` sends one tiny real read; red, it opens the Reviewer-down issue and `check.sh` holds every machinery pull request until a canary passes; `.github/workflows/monitor.yml` opens it too for an ask no read follows. A red canary is answered first with one plain canary dispatched on `main` (`workflow_dispatch` with its `probe` input left at none: the same one tiny real read, with no limit added to it) by the session that merged, else the next to start: green lifts the hold, and that session re-runs each held `check` once, since nothing else wakes them; red, the change is reverted unless a smaller repair is shown safer (4 November 2026: run 41921982230 lifted the hold the canary after #338 set on the reviewer's empty finding; agreed on 5 November 2026 by the CTO and the consultant's stand-in, the consultant being unreachable from a cloud session (`library/carries-sessions.md`), under `juku-library/DECISION-0023-STANDING-RULING.md#Decision 0023: an agreed, reviewed rule change counts as his ruling`, his words: *"a change to how we build that Astra and the CTO agree, and that passes the independent review, counts as my ruling"*, the stand-in being the route `library/carries-sessions.md`, *Its sessions*, gives when the consultant cannot be reached; the debate is on [#352](https://github.com/Adonis80/how-we-build/issues/352#issuecomment-6646232681)). **The emergency route**, for reviewer repair or revert only: an admin merges with GitHub's own bypass, the pull request linking the outage issue and the exact repair commit and naming the check bypassed, recorded as an emergency exception, never a clean review; a canary runs after it lands.
