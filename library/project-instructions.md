# What a Project holds, and who sets it

Scope: every Project under this rulebook, the consultant's too. Open when: a Project's instructions differ from their template, or text for the Chairman changes.

**Which repository a chat Project reads (the Chairman's ruling, 11 September 2026).** The Juku OS Project — the chat Project named for this system — reads this repository and uses the README's map as the whole register of what exists, opening a product repository only when it needs live detail; its instructions are `library/project-template-juku-os.md`. The Hemz OS Project reads `Adonis80/Hemz-OS` plus the global rules here; the Myst Project reads `Adonis80/myst` plus the same; the Phena Project reads `Adonis80/phena` plus the same. This is where to read, not permission to read: each Project's own GitHub connection is proved by fetching live commits and open pull requests from inside that Project, because a successful read somewhere else proves nothing for it. Reuse this register; never start a second map.

**Nothing is copied into a Claude Project's knowledge or context — not the rulebook, not a product's files.** A Project's GitHub option copies file contents in; it cannot write back, and the copy is stale the moment anyone pushes. Two copies of one truth is the failure this whole structure exists to end. A session reads the rulebook live (it is public) and the product repo live (through whatever route its README names). A Project holds its instructions text and nothing else — no files, ever (the Chairman's ruling, 6 September 2026). That instructions text is therefore the only place a session can be told how to reach a private repo, and it has no version history: if it is ever lost or wrong, re-paste it from the template (`library/project-template-product.md`).

**A Project's instructions write themselves from here, and so do the consultant's (decision 0015).** At a session's start it pins one commit of protected `main` and compares the installed text with its template filled at that commit: `library/project-template-product.md` for a product, `library/project-template-juku-os.md` for the Juku OS Project, the block in `library/consultant-instructions.md` for a consultant's Project. Each `<role>` is filled from that registry role as "picker label (effort)"; a change to a role the template does not name rewrites nothing. If they differ it sets them, first and once: every placeholder filled, nothing saved while any `<…>` remains, saved whole, reloaded and read back, the commit named in the handover. Anything product-specific in the old text goes to its `AGENTS.md` by pull request. A read-back proves the picker label, never the model behind it.

**The session sets them; the Chairman is handed no paste (his ruling, 14 September 2026).** It works in the Claude app's built-in browser (*The two stacks*), signed in to `claude.ai` by him: `claude.ai/projects` → *New project* → the name and one line saying what it is → *Create project* → *Instructions* → *Edit instructions* → the template, whole → *Save instructions*. An existing Project is the same route from its own page. A consultant's Project in ChatGPT is set by its own route, through the Chrome extension, and read back there; the Claude steps prove nothing for it. The session then reloads the page, reopens the instructions, reads them back and says what it set — a Project is not reported as done on the strength of having typed into it. If that browser is not signed in, he is handed that one tap and nothing else. The text whole is for a session with no Mac connected, and that is the exception, not the route.

**Text for the Chairman is handed over whole.** When the template (`library/project-template-product.md`), the consultant's standing instructions, or any text he pastes somewhere changes, he is given the complete new text to replace the old with — never a sentence to find and splice in, which invites the very error the template exists to prevent.
