# The model registry

Scope: every repository under this rulebook, in either stack. Open when: asking which model holds a role, what a read resolved to, or switching the model behind a role.

**One file names models: `model-registry/registry.json`** ([decision 0008](https://github.com/Adonis80/how-we-build/issues/103)). Everything else asks for a role: `reviewer-main`, `reviewer-risky`, `reviewer-frontend`, `coder-fast`, `coder-max`, `frontend-fast`, `frontend-max`, `agent-fast`, `max-subagent`, and the debate's seats, conversation roles no caller calls (decision 0015, `library/consultant.md`). `check.sh` refuses a model id anywhere else in this repository, and each fact in the registry carries the date it was checked and its source.

**Asking for a role.** `python3 model-registry/resolve.py model-registry/registry.json <role>` prints what the role resolves to: the model, provider, calling interface, credential, effort and fallback role. Add a field's name for that field alone. A role that cannot resolve cleanly (unknown, a blocked model, an effort the model does not take) is an error, never a default. Calls go through `model-registry/ask.py`, the OpenAI-compatible interface OpenRouter speaks today and a LiteLLM proxy or a direct provider would speak tomorrow, so a new provider is a registry entry and an Actions secret, never code.

**Who reads what.** The cheaper model reads first (decision 0008). An ordinary change goes to `reviewer-main`; one in a risky class, or with any file whose kind the list does not know, to `reviewer-risky`, read as the same selection with the registry beside it (decision 0018). Nothing stands behind either (R-2026-10-05ca): a role that gives no verdict leaves the commit unread and the gate red, and `review.yml` tells him on one issue, so the work is finding why the reviewer was lost and fixing it. `reviewer-main` is open-weight (R-2026-10-05ca), is not the lead's own model (R-2026-09-29ca), and reads at max (R-2026-09-28ca). `reviewer-risky` is the exception to all three: high effort, for rare risky cases only (R-2026-10-09ca, [decision 0019](../juku-library/DECISION-0019-OPUS-READS-RARE-RISKY.md)), on the Claude plan, so it spends no review cash. *Rare* means the risky list holds the six classes, and decision 0008's two prerequisites, and nothing else. `review-gate.py` holds each role at its own effort. The reviewers read the registry from `main`, so a pull request never picks its own reviewer.

**Seeing what a read resolved to.** The spend line every verdict ends with (`library/reviewer.md`), with bytes in and out and whether the fallback read it, on the check run, the comment and the job's summary.

**Switching.** Change the role's `model` (or its `effort` or `fallback`) in `registry.json`, with the new model's entry, its `checked` date and its `source`. `resolve.py --check` and `check.sh` must pass. It is a risky change, read by `reviewer-risky`. If the pinned Claude Code does not know the model, the pin moves in both reviewers and `review-gate.py`, proved first on a full-size read (#130). Rolling back is reverting it, while the role that reads the revert still answers.

**A product's code goes to the registry's provider**, not to Anthropic alone (R-2026-10-06ca). `review-product.yml` reads through the same roles and caller as this repository, and `ask.py` sends nothing that does not ask providers to promise not to store or train on it: a promise, not proof.

Re-reading only what changed is built for product reads (`library/reviewer.md`, *Asking*; not yet shown on a cited run). **Not built yet** (decision 0008's later steps): the weekly model check that proposes a registry pull request, and the main coder on an open-weight model.
