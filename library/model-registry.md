# The model registry

Scope: every repository under this rulebook, in either stack. Open when: asking which model holds a role, what a read resolved to, or switching the model behind a role.

**One file names models: `model-registry/registry.json`** ([decision 0008](https://github.com/Adonis80/how-we-build/issues/103)). Everything else asks for a role: `reviewer-main`, `reviewer-risky`, `reviewer-frontend`, `coder-fast`, `coder-max`, `frontend-fast`, `frontend-max`, `agent-fast`, `max-subagent`, and the debate's seats, conversation roles no caller calls (decision 0015, `library/consultant-debate.md`). `check.sh` refuses a model id anywhere else in this repository, and each fact in the registry carries the date it was checked and its source.

**Asking for a role.** `python3 model-registry/resolve.py model-registry/registry.json <role>` prints what the role resolves to: the model, provider, calling interface, credential, effort and fallback role. Add a field's name for that field alone. A role that cannot resolve cleanly (unknown, a blocked model, an effort the model does not take) is an error, never a default. Calls go through `model-registry/ask.py`, the OpenAI-compatible interface OpenRouter speaks today and a LiteLLM proxy or a direct provider would speak tomorrow, so a new provider is a registry entry and an Actions secret, never code.

**Who reads what.** The cheaper model reads first (decision 0008). An ordinary change goes to `reviewer-main`; one in a risky class, or with any file whose kind the list does not know, to `reviewer-risky`, read whole. Nothing stands behind either (his rulings of 5 and 6 October 2026, quoted in the registry): a role that gives no verdict leaves the commit unread and the gate red, and `review.yml` tells him on one issue, so the work is finding why GLM was lost and fixing it. No reviewer role holds the lead's own model (his ruling, 29 September 2026: *"we weren't using Opus at max effort as a reviewer because it's the same family as the main coder"*), and only open-weight models review (his ruling, 5 October 2026); a new lead rechecks them. Both read at max: his ruling of 28 September 2026, *"every read at max"*, set in the registry and held by `review-gate.py` since [#123](https://github.com/Adonis80/how-we-build/pull/123), which quotes it whole. The reviewers read the registry from `main`, so a pull request never picks its own reviewer. Its first live reads, each with its spend line, are cited on [#103](https://github.com/Adonis80/how-we-build/issues/103).

**Seeing what a read resolved to.** Every verdict ends with a spend line: class, role, exact model, effort, bytes and tokens in and out, the cost the provider reported, minutes, and whether the fallback read it. It is on the check run, on the comment and in the job's summary.

**Switching.** Change the role's `model` (or its `effort` or `fallback`) in `registry.json`, with the new model's entry, its `checked` date and its `source`. `resolve.py --check` and `check.sh` must pass. It is a risky change, read by `reviewer-risky`. If the pinned Claude Code does not know the model, the pin moves in both reviewers and `review-gate.py`, proved first on a full-size read (#130). Rolling back is reverting it, while the role that reads the revert still answers.

**A product's code goes to the registry's provider** (his ruling, 6 October 2026: *"remove this rule where Anthropic is the only provider that is allowed the products private code"*). `review-product.yml` reads through the same roles and caller as this repository (first run [Adonis80/Hemz-OS#74](https://github.com/Adonis80/Hemz-OS/pull/74), run 37511951196), and `ask.py` sends nothing that does not ask providers to promise not to store or train on it: a promise, not proof.
