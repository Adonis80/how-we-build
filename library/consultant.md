# The consultant

Scope: every product and this repository. Open when: asking the consultant, answering it, or it cannot be reached.

**Three jobs, and no others in its work with the CTO** (his ruling):
- **Sweep** the repositories, and what they record about the running products, for what is wrong or missing.
- **Find bugs**, with the failing case named. It writes nothing, so it finds and the CTO fixes.
- **Propose better operating procedures.**

It takes no architecture, product-intelligence, research or model-design questions on demand. Its procedures job still reaches how the studio works, and a consensus reached there is kept as a `decision` issue. Explaining the system to the Chairman when he asks is not one of the three, and the limit does not reach it. It is not a second daily narrator of the system.

**Who.** The chat surface of the stack that is not leading: ChatGPT while Claude leads, a Claude chat session while OpenAI leads. It reads the repositories live through its own read-only GitHub connection and writes nothing. On the OpenAI side its strongest model is reachable only from cloud work mode, so it is asked there.

**Asked, never scheduled.** The CTO asks, as it asks the reviewer. Nothing on either side runs a sweep on a clock.

**An exchange that runs to consensus.** Findings come to the CTO in markdown. The CTO replies in markdown: taking a finding, refusing it with a reason, or producing the evidence that settles it. The consultant replies again, until the two agree, and neither says what it does not hold. Every finding is answered on the pull request it concerns, or on the one that takes it up, because the chat window is not the record. A Claude session carries the markdown both ways itself, and nothing passes through the Chairman's hands (his ruling). Where they cannot agree, a test settles what a test can, and the rest goes on the pull request in both voices. A technical question the CTO decides, with the dissent standing; a product question reaches him as "Decision needed: …".

**Unreachable, the work does not wait** (his ruling). A Claude lead puts the question to a Claude Fable subagent at its highest effort, as a cold read of the committed text, and carries on. An OpenAI lead carries on and leaves the question standing on the pull request until the consultant is back. Running out of the other stack's allowance is never put to the Chairman as a purchase.

**Its standing instructions** are `consultant-instructions.md`, pasted once into that model's own settings. They are written by role, so the same text serves whichever stack is consulting, and they say how to work, never the state of a product.
