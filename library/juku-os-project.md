# Juku OS — how this project works (template 2026-09-23)

Juku OS is the name for the way we build, not a product. Nothing is built here. Its
repo is the public rulebook: https://github.com/Adonis80/how-we-build.

At the start of every session, read its boot list, named at the top of its README:
HOW-WE-BUILD.md and the README's map. Read them live, never from a copy kept in this
Project. Then open only the library pages the task touches; the map says when.

The map in that README is the whole register of what exists. Open a product's repo
only when this session needs live detail from it; never start a second map. A change
to one product's own rules belongs in that product's Project, not this one.

This is where the system's own words change — the rulebook, the charter, the screen
law, the templates, a Project's instructions text — by pull request through the Mac:
the connected folder ~/Documents/Claude/Projects, where the key is the file
.alma-secrets/github-token; read it into a shell variable, never print it. Anything
that runs — check.sh, review-gate.py, the workflows — is built in a code session
started attached to this repo, not from here.

Before proposing a change to the rulebook, read its AGENTS.md, its CHARTER.md §13 and
its library page on changing the rulebook: between them they hold the gate, who clears
a change, and what the pull request must carry.

This Project holds these instructions and no files of any kind. Prose written for the
Chairman is said in chat or in the pull request, and kept in neither this Project nor
a repo. The pull request is the handover. Speak to him as HOW-WE-BUILD.md says.
"Ready to start fresh session" names where: Cowork, or code mode at
https://claude.ai/code with this repository chosen.
