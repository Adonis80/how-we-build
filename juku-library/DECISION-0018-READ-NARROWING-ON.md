**Decision 0018 — no review reads the whole repository: every read is a selection, risky or not (9 October 2026)**

Parties: the Chairman's ruling, and the CTO (Claude) who built it. **Live** once the pull request that adds this record merges. It is a ruling carried out, not a debate: no consultant round stands behind it, and none was needed, because decision 0016 had already agreed what a localised read must keep.

**His ruling, 9 October 2026, whole:** *"Yes, I want the full read narrowing switched on now."* Recorded on [#171](https://github.com/Adonis80/how-we-build/pull/171). It was given after the CTO's account that a risky rulebook read is handed every file whole (1,246,617 bytes at e85d281, about three quarters of it code; `review-gate.py` alone 497,240), and that decision 0016's route was offline preparation, promoted only on evidence and his yes.

**His ruling, 8 October 2026, whole (decision 0017):** *"Hold on, the cap doesn't appear to work. We tried that in the past. And what happens is we just run into errors in the system that need updates, but we are simply forced to not apply the update, meaning the failure continues because we can't fix it because we've got a cap. The answer must be that we should always be allowed to fix the rulebook and to upgrade the rulebook, but we must do so in a way that removes all of the dead information at the same time. Do you agree? And how can we apply this principle across the board? The only measure of success is the building of world-class software that we can monetize as fast as possible. That's the only metric that works."* Read here as: fix and upgrade freely, and delete what a change supersedes in the same change.

**What is built.**

1. **Risky stays a class, and stops meaning every file.** It still picks `reviewer-risky` at max. Every class, risky included, is given `model-registry/context.py`'s selection: `HOW-WE-BUILD.md`; the README's index; each touched file, whole up to 40 KB, past that the sections, steps or functions its hunks fall in; the partner map both ways; every page naming a touched file; on a code or risky read the registry; everything else named with its size.
2. **The partner map carries the gate**: `check.sh`, `review-gate.py`, `check.yml`, `review.yml`, `wake.yml`, `review-product.yml`, `product-reads/` and the registry's code. A partner past 40 KB is given as its sections naming the change's files, or, when those are past 40 KB too, as their names.
3. **More comes only when the reader asks.** A `needs-context` finding names a file or one unit of one, `path#heading`, `path#function` or `path#step name`, and the one re-read is given every unit whole or the read stays incomplete (#170). A product's re-read may ask for `PRODUCT.md#<heading>` or `roadmap.json#<item id>` and gets that unit alone. `more()`'s 200 KB is not raised (decision 0017, point 4): a reader fetches less instead.
4. **Products, the same way.** A touched file is whole only up to 40 KB; past that, and the roadmap and `PRODUCT.md` whenever touched, it is the parts the change touches: the roadmap's touched items, each alone. The pick by the title's item stays the title's and never sees the diff.
5. **The self-tests that held "a risky change is given every file whole" are replaced**, in the same change, by coverage cases: an omitted partner that changes the verdict is selected (the workflow that runs a check, the function of a large gate naming it), and a page naming nothing changed is left out.

**What it supersedes.** Decision 0016, amendments E (the offline `review-pilot/` folder) and F (the paid replay before promotion). Decision 0015's item 10 (*Risky reads unchanged*) and its follow-up, fully. Decision 0014's G and H only where they kept a risky read whole; cold review and max effort stand.

**What still holds.** Decision 0016's coverage before ceilings (C): selection covers partners both ways, and a ceiling is never met by truncating. #170's recovery: every requested file or unit supplied whole, or the read stays incomplete. Replace, then delete (G): the every-file-whole invariant is deleted here, not left beside its replacement. Decision 0017's size readings: every size this change prints is a reading, never a failure.

**The last full read.** `review.yml` runs from `main`, so the pull request that adds this record is itself read the old way, every file whole, about 1.3 MB. Every read after it is a selection.

**Strongest objection left.** A partner the map does not name can still be missed. The reader is told what was left out, with sizes, and asks; a read short of what it asked for never clears.
