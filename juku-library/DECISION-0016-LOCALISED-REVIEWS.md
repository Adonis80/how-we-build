## His words (7 Oct 2026)
"Why are we asking GLM to complete such massive tasks? Because this is the whole point of the efficiency protocol, was to reduce the amount of reading the reviewer needs to do. It should not be reading the entire repo for minor changes."
"I build juku os, and by extension all projects, to be modular. does this not mean that we develop smaller manageable modules that work beautifully and independently. this in turn should mean that updating one part should not break another part. and that means that you do not have to read the entire repo. the read should be hyper localised."

## Facts that started it
- how-we-build #168 (6 files, ~38 lines) is risky-class, so GLM 5.3 at max read every .md/.sh/.py/.yml whole: 1,258,814 bytes, 319,376 tokens. Twice the provider failed mid-answer (run 37684383558: "caller: finish error"), cost 0, gate shut.
- The broad rulebook read was deliberate (decision 0010 item 1a; decision 0014 position F kept it pending measurement). Product reads already localise (#86, #166).
- review-gate.py is 479,069 bytes. needs-context recovery exists today; more() refuses additions over 200,000 bytes.

## What was agreed
1. **Selection by affected contract.** A read gets the diff, touched files, a small fixed core (HOW-WE-BUILD.md, the reviewer's brief, the gate's own rule page), and everything that owns, implements, consumes or tests the contract being changed, from an extended trusted partner map. Path and title search (one hop, both directions) starts discovery; it never ends it.
2. **Both trees searched:** baseline and proposed, old paths included for deletions and renames. **BREAK FIX:** both trees are pinned, and every supplied file or section is labelled baseline or proposed, so content from either tree can reach the reviewer, including a deleted contract or the former version of a changed path.
3. **Protected main decides:** selector, partner map and reviewer instructions come from main only; a PR cannot narrow its own review.
4. **Not operating dependencies:** README indexes and frozen decision records do not drag pages into a read.
5. **Recovery:** reuse the existing needs-context path (one cold reread, counted; a real blocker cannot be laundered; a remaining shortfall never clears). Requested paths validated against the pinned tree. Requesting a partially supplied file supplies it whole on the single reread within declared request and spend bounds, else the read stays incomplete; more()'s 200,000-byte refusal is repaired for that case and proved by a large-file recovery case before rollout. Region requests wait. **BREAK FIX (blocker, a live defect today):** the complete requested set is kept outside the model's answer, and every requested file and version must be supplied whole before the reread. A missing, invalid, oversized or excess request leaves the read incomplete and can never be silently dropped (today `needed()` trims requests to three paths and `more()` succeeds when any one is supplied). A clean second answer cannot erase an unmet request. Proved by the breaker's three cases (small file plus missing file; small file plus the 479 KB file; four valid files) all refusing clearance, including after the byte limit is raised. This repair lands first, on its own, before any other step, because it protects today's gate.
6. **Large files:** 40 KB is a pilot trigger, not a completeness limit. A large touched file is supplied structurally: changed enclosing functions or sections, the same-file definitions they depend on (imports, decorators, constants, fixture tables, relevant callers, dispatch), plus its outline. Where the extractor cannot establish a boundary it widens, never silently omits.
7. **Machine checks** carry cross-page invariants we rely on; each new check proved by a failing example. They do not claim every prose contradiction is encoded.
8. **Boundaries:** unexpected dependencies expose a boundary defect; legitimate contract changes widen the read to their affected consumers. Splitting a PR must never hide coupling.
9. **Still read broadly:** selector, partner-map, classification or context-recovery changes (through the pilot); studio-wide authority or contract changes (every affected operating rule and its enforcement and consumers); unresolved dependencies (widen, or the gate stays shut). Risky keeps max effort.
10. **Proof before rollout:** deterministic coverage check first; then replay a predeclared corpus (cross-page contradictions, removed references, indirect consumers, gate changes, missing-context recovery) on the original defective commits stripped of findings and fixes, plus seeded faults for gaps history lacks and clean counterparts for false blockers. Same model, effort and route; retries, incomplete reads, time to usable verdict and all-attempt cost counted. A silently cleared known blocker fails the pilot. Passing supports a bounded rollout only. **BREAK FIX:** the coverage check's expected files and sections are predeclared per case independently of the partner map (otherwise map and check agree while a missing consumer stays invisible), and some cases are held back from tuning the selector. The pilot is scored on the final gate outcome: a known blocker reported only as advisory still clears, so it fails the pilot. Clean counterparts must reach a usable completion, so refusing everything cannot pass. **BREAK FIX:** the replay runs without the signing credential and its results can never clear a real commit.
11. **Scope and order:** rulebook reads only (products already localise). #167 and #168 keep today's read. (0) **BREAK FIX:** the recovery repair in item 5; (1) decision record and extended partner map; (2) coverage check and replay corpus; (3) localised selector run offline against the corpus; (4) bounded rollout to non-selector-class rulebook changes; (5) the gate split.
12. **Gate split (later, separate slice):** separate runtime gate logic from test machinery, then extract further modules only where demonstrated contract seams justify them. Preserve test cases, mutation coverage, entry points, refusal precedence, exit codes and CI wiring; compare baseline and candidate behaviour on the same fixtures; moved modules enter the partner map and check inputs. Read broadly once, as selector-class.
13. **Evidence kept apart:** the GLM first-party route trial holds context fixed; the context pilot holds route fixed.

## What changed whose mind
- **Claude moved:** one hop is not a boundary (affected contracts instead); item 5 reworded (contract changes legitimately widen); search both trees; indexes and frozen records excluded; reuse needs-context instead of a new NEED syntax; the full replay design; structural large-file context with same-file dependencies; complete-file recovery repair; gate split led by demonstrated ownership, not five assumed labels; #168 proves operational failure, not that size caused it.
- **Astra moved:** the operational failures justify reconsidering the broad default now, not after further waiting.
- **Breaker moved the CTO:** recovery must enforce fulfilment of every request (a live hole); independent expectations and held-out cases for coverage; version labels for path requests; replay kept away from the signing credential.

## Strongest objection left
An undeclared dependency can still escape discovery. The pilot tests that risk; it cannot prove universal completeness.

## Break test verdict (8 Oct 2026)
DOES NOT STAND as first written: one blocker (recovery can clear with unmet requests; reproduced locally against live main 3b914f6 with canned answers, no paid calls) and three weaknesses, all taken above. It found no objection to the protected selector, retained effort, the broad exceptions, the separate route trial or the deferred gate split. Not verified by it: whether GLM has produced that sequence in practice, the corpus or scoring harness, a replay harness, the future selector.

## Before money is spent
The replay runs paid reads; it comes to the Chairman as its own yes, with its estimated cost. Steps (0) to (2) spend nothing beyond their own pull-request reads.

## Not checked
Raw provider responses, a historical replay corpus, every operating page, private product boundaries, any candidate extractor, selector or split implementation, the first-party route trial.

## Part 2 — the second debate, 8 October 2026

**Asked:** the Chairman, 8 October 2026, whole: *"The problem is I want to ship products but in doing so the Juku OS system is wasting all of my tokens by reading unnecessarily the entire repo for every little change. This was the whole point of what we were working on. If I was to abandon the efficiency protocol, it would mean that I have to accept that I am wasting all of my tokens without fixing it. But then if I try to fix it, the rule book is too big and you get stuck in a death loop. Also, the rule book this failure class of the rule book getting too big to manage and AI sessions being overwhelmed with working on too much at the same time is exactly what we attempted to solve at the very beginning by working in a modular fashion. The whole point of being modular is that you don't work on the entire repo. You work on work packages that are deliberately small and independent so that all you need to do is to perfect that module and it will work seamlessly with the rest of the system. But something has gone wrong because, as you said yourself, somehow the rule book has expanded to over a thousand pages. This should have never been the case. The rule book needs to have a thorough cleanup because there must be lots of inefficiency in such a massive document. There must be unnecessary detail. There must be conflicting information. There must be the old failure class of um, failing to delete old stale information. And you're simply stacking new rules on top of old rules. This is precisely what Juku OS was designed to prevent. I want you to look at this again with Astra set at high effort. And I want you to both ensure that we can ship profitable products as fast as possible. That means that the coding is efficient and the reviewing process is efficient. You're not wasting tokens reading the entire repo. If I've got any misguided assumptions, then feel free to push back. **The Chairman's assumptions, answered.** His principle stands: a change should load the parts needed to build and check it. The rules a session reads at its start are small; about three quarters of the repository's bytes are Python, YAML and shell, and it is a risky-class rulebook review, not product work, that is handed nearly all of it. **Amendments to Part 1, dated 8 October 2026:**

- **A. Diagnosis before a size wall is declared.** From retained evidence only. Where it cannot name the cause, the cause is unknown and nothing is built on a guess.
- **B. The current reviewer route first.** The emergency route in `library/reviewer-parking.md` only within its own scope. Any other exception goes to the breaker and then to the Chairman for his explicit permission for that exact exception. The consultant is a conversation seat, never a substitute reviewer; his request to clean up is not permission to waive a check.
- **C. Coverage before ceilings.** Selection covers contract partners in both directions, consumers, tests and standing authority, with adversarial cases where the omitted partner changes the verdict. A ceiling applies to the whole assembled request and the allowed recovery; when required context does not fit, the change shrinks or parks, and nothing is truncated to fit. The all-requested-files recovery of #170 is preserved. The selector and its coupled proofs change together.
- **D. No new session rule.** `library/session-changeover.md` stands: continue while retained context helps, stop when work cannot move or context degrades. A rule not applied is not answered with another rule.
- **E. The partner map is not extended in place** (corrects Part 1's order, step 1, and the brief written from it). `select()` uses the map on every ordinary read, so extending it is a live change: one plausible entry, added in memory, took one ordinary read from 12,857 to 57,407 content bytes. Instead ONE offline-preparation pull request adds a temporary top-level folder, `review-pilot/`, admitted by name in `check.sh`: the candidate map, an offline selector entry that takes the map as an argument, the coverage and refusal checks, and the replay corpus with its predeclared expectations and scoring. Production selection and both reviewer workflows stay unchanged, and a check proves production cannot use the candidate. Isolation means the candidate cannot control production selection or gain execution authority; the normal broad read still sees the pilot's files as material under review. If that pull request's own read fails, it is parked: it repairs no outage, so the emergency route does not apply to it.
- **F. Evidence before promotion.** Free checks first, and nothing is spent on a candidate they reject. The size survey runs over the last twenty merged pull requests on their pinned historical trees and assembled requests. Then a small, contract-diverse paired replay, context the only variable: known-defective heads or independently specified mutations, with correct controls; one clear target defect per decisive negative case, or each targeted blocking obligation tracked; the candidate frozen before evaluation cases are revealed; cases used for tuning become regression tests; decision criteria and stop conditions predeclared; signing credential absent. The estimate covers both arms, permitted recovery and maximum attempts, and is an estimate. The breaker precedes the request for paid work.
- **G. Promotion replaces, then removes.** With the evidence and his yes, the candidate replaces the live map in one pull request, the every-file-whole invariant is replaced there by coverage-and-refusal cases, and those durable cases land in their retained owner. `review-pilot/` is deleted on promotion or on abandonment. The gate split follows as Part 1, item 12: runtime apart from checks, shared contracts owned once, behaviour tests in place of wording tests where they prove the same refusal.
- **H. Product delivery and ordinary cleanup proceed.** Eligible product work is the first priority and stops only where its own dependency or safety condition requires. Stale wording is removed in dependency-coherent batches, every operative condition kept whole at its triggered owner, each conflict listed in its pull request. The existing handover evidence and the month review are the measurement; no standing measurement service is added.
