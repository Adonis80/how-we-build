# Legacy roadmap

**Status:** idea bank only. Not instructions, not approved work, not a second roadmap.

This file preserves potentially valuable ideas recovered from retired Juku-era repositories before those repositories are removed. Nothing here is active unless Dhayan deliberately promotes it into an active product's `PRODUCT.md` or `roadmap.json`.

## Product ideas worth remembering

- **Personal AI command centre** — one simple front end for working across multiple AI providers and tools.
- **Provider-independent AI routing** — allow the underlying model/provider to change without changing the user's workflow.
- **Plugin / module ecosystem** — narrow capabilities can be added without turning the core product into a general-purpose platform.
- **No-code module creator** — a guided Studio where a non-technical person describes a small tool or learning module and publishes it.
- **White-label products** — the same underlying capability can power separately branded products or communities when there is proven demand.
- **Contract-first reusable modules** — calculators, records, AI tools and workflows described by a small stable contract rather than copied implementations.
- **Shared intelligence with separate products** — reusable knowledge or capability can sit behind multiple specialist products while each product keeps its own product truth.

## Social / learning ideas

- User-generated micro-lessons and structured knowledge.
- Voting, reputation, visible progression and domain-specific gamification.
- A lightweight internal currency (`Juice`) for tips, boosts, cosmetics or paid AI usage.
- Invite-led growth and referral graphs, including proximity/NFC concepts.
- Daily challenges, streaks and shareable results.
- Live learning / broadcast sessions with audience participation and tipping.
- A visual world or map showing communities and connections.
- A companion/creature progression layer (`Jukumon`) as an optional retention/cosmetic system.
- Cross-domain profiles and reputation, while keeping each specialist domain understandable on its own.

## Builder / operating-system ideas

- **Success = less work for Dhayan.** The system should absorb coordination rather than create work for him.
- Fresh sessions should recover from durable repository truth rather than chat history.
- Automated health checks should surface real breakage rather than create dashboards for their own sake.
- Independent adversarial review is useful when it tests a concrete change; multiple permanent agent roles are not automatically useful.
- Design should be reviewed against explicit screen rules and real states, not merely visual polish.
- Performance, accessibility, reduced-motion and end-to-end journeys are useful acceptance evidence when proportionate to the product.
- Cost should scale only when real usage or revenue justifies it.
- Secrets, tokens and environment values remain outside product documentation and must never be copied into this file.

## Alterations-product ideas recovered from Alma-era work

- Pricing should be derived from real work rather than copied historical prices.
- One source for shared numbers; never type the same rate or timing in multiple places.
- Unknown or estimated values should remain visibly unknown/estimated until confirmed.
- Staff and customer views should expose different levels of detail.
- Formula logic can be assembled from reusable work operations rather than one-off price lines.
- Human review should remain available for work that exceeds safe automatic-pricing boundaries.

## Explicitly retired machinery

These appeared in earlier systems but are **not recommendations to rebuild**:

- permanent AI CEO / orchestration hierarchy;
- trigger queues and clock-driven agent chains;
- separate memory databases for project state;
- Guardian/Hermes control planes;
- duplicated source-of-truth documents across Obsidian, local folders and GitHub;
- large standing agent rosters;
- platform infrastructure built before a product proves it needs it;
- version/governance machinery added merely because a future multi-product platform might need it.

## Promotion rule

An item leaves this file only when Dhayan chooses to use it in a real product. At that point, write the smallest current version into that product's own source of truth and leave this file as historical inspiration only.
