# AGENTS.md — how-we-build

What is particular here: this repository is the rulebook, not a product, and changes only by pull request against protected `main`. Adding a rule, step, file, check or agent needs the charter's gate (§13) or the Chairman's ruling; removing one, or correcting wording, needs neither. The proposer does not clear its own addition — the cold review does (§13). So the CTO merges its own addition only on a commit the reviewer read and left no finding on, never one where it answered a finding — that puts the proposer back in the judge's seat. Disagreeing with a finding is not clearance: it goes to the Chairman, who settles it. `check.sh` holds that rule rather than a hand: green only on a commit a reviewer read and left nothing on, red while the head carries a finding — the answer to a finding is a push, which makes a commit the reviewer reads afresh. From 17 September 2026 it can count a second reviewer by that reviewer's own login: Codex is the primary and reads first; a backup counts only where it refused this head and has not answered since, and never to clear `review-gate.py`, `check.sh` or anything under `.github/`. No such login exists yet, so none is counted; the README says why. The Chairman's hand is not the control and never was — he approves by looking, not by reading a diff (his ruling, 14 September 2026). `check.sh` is the only check. There is no `roadmap.json`: the queue here is the open pull requests, oldest first.

## Review guidelines
The brief is in `README.md`, *The independent reviewer*; these lines repeat the least the tool needs in front of it. Address the CTO. Form your view from the diff and the existing pages before the pull request's own account. Most serious first, each with what is wrong, what you would do instead, and how sure you are; say what you checked, what you did not, and what a diff alone cannot tell. Two rounds at most, then as the brief says. Prefer a deletion to another exception; do not manufacture disagreement. Never write a file into this repository. Hazards particular here: an addition to how we build without the gate or the Chairman's ruling; the operating page over its cap, or a shorter page quietly requiring less than the one it replaces; a file not on the list; two copies of one truth; provider-specific detail leaking into a global rule; a rule kept in prose that `check.sh` could hold; a claim that *build* is self-sufficient when a fresh session in either stack could not recover the work; and, since the gate admits a reviewer of the lead's own vendor, anything letting it clear a gate change, or a branch choose or instruct the reviewer that reads it.
