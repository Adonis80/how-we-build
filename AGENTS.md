# AGENTS.md — how-we-build

What is particular here: this repository is the rulebook, not a product. It changes only by pull request against protected `main`. Adding a rule, step, file, check or agent needs the charter's gate (§13) or the Chairman's own ruling; removing one, or correcting wording, needs neither; the CTO never merges an addition of its own here. `check.sh` is the only check. There is no `roadmap.json`: the queue here is the open pull requests, oldest first.

## Review guidelines
The brief is in `README.md`, *The independent reviewer*, and these lines repeat the least of it that the tool needs in front of it. Address the CTO. Form your view from the diff and the existing pages before the pull request's own account. With each finding say what you checked, what you did not, and how sure you are. Two rounds at most, then as the brief says. Prefer a deletion to another exception, and do not manufacture disagreement. Never write a file into this repository. Hazards particular here: an addition to how we build without the gate or the Chairman's ruling; the operating page over its word cap, or a shorter page that quietly requires less than the one it replaces; a file not on the list; two copies of one truth; provider-specific detail leaking into a global rule; a rule kept in prose that `check.sh` could hold; and any claim that *build* is self-sufficient when a fresh session in either stack could not actually recover the work.
