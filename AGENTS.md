# AGENTS.md — how-we-build

What is particular here: this repository is the rulebook, not a product. It changes only by pull request against protected `main`. Adding a rule, step, file, check or agent needs the charter's gate (§13) or the Chairman's own ruling; removing one, or correcting wording, needs neither. The proposer does not clear its own addition — the cold review does (§13). So the CTO may merge an addition of its own only on a commit a reviewer has read and left no finding on — never on one where it answered a finding, which would put the proposer back in the seat of the judge. Disagreeing with a finding is not clearance: the disagreement goes to the Chairman, who settles it. `check.sh` holds that rule rather than a hand: it is green only on a commit a reviewer has read and left nothing on, and red while the head carries a finding — the answer to a finding is a push, and the push makes a commit the reviewer reads afresh. The Chairman's hand is not the control and never was one — he approves by looking, not by reading a diff (his ruling, 14 September 2026). `check.sh` is the only check; `.github/workflows/review.yml` is a reviewer it waits for, not a second check. There is no `roadmap.json`: the queue here is the open pull requests, oldest first.

**One reviewer, and no door between two (his ruling, 22 September 2026: *"Do not use Codex as a reviewer"*).** Who it is is `DEFAULT_REVIEWER` at the top of `review-gate.py`, and it answers one way only: as a check run created by the `juku-reviewer` GitHub App — a login no branch can wear, a signal no writer can edit or erase. Its private key sits in the `reviewer` environment, which admits `main` alone, and `.github/workflows/door.yml` is the standing proof of that rather than the claim. Nothing is read out of prose any more: a comment and a submitted review were Codex's two voices and the gate counts neither, which `_check_routes` enforces by refusing a register entry that carries a login at all.

**What that costs, said here because the reviewer reading this needs to know it.** The one class of the rulebook's cross-vendor list that arises here — a change to `check.sh`, `review-gate.py` or anything under `.github/workflows/` — was held in the gate: it opened on Codex's clean read alone. With one vendor that rule had no satisfiable form, and it is gone rather than pointed at somebody else, so **a gate change now clears on the same single read as anything else**. Worse, the check that judges a pull request is the pull request's own — `check.yml` checks the head out and runs that tree's `check.sh` — so a change to the gate is judged by the gate it proposes. The check prints a `note:` line saying so on any such pull request, green or red. It shuts nothing. On a gate change, read the diff rather than the green, and treat that class as the one where a finding is worth more than a clean pass. What ends this is a second reviewer answering, not a sentence.

## Review guidelines
The brief is in `README.md`, *The independent reviewer*, and these lines repeat the least of it that the tool needs in front of it. Address the CTO. Form your view from the diff and the existing pages before the pull request's own account. With each finding say what you checked, what you did not, and how sure you are. Two rounds at most, then as the brief says. Prefer a deletion to another exception, and do not manufacture disagreement. Never write a file into this repository. Hazards particular here: an addition to how we build without the gate or the Chairman's ruling; the operating page over its word cap, or a shorter page that quietly requires less than the one it replaces; a file not on the list; two copies of one truth; provider-specific detail leaking into a global rule; a rule kept in prose that `check.sh` could hold; any claim that *build* is self-sufficient when a fresh session in either stack could not actually recover the work; a gate change whose `note:` line is missing, or waved through on the strength of a green the change itself produced; the gate's register of reviewers and the wake job's condition drifting apart, so a read lands that nothing re-runs the check for; the reviewer workflow gaining any trigger beyond `issue_comment`, or losing its `environment: reviewer` line, either of which lets a branch run a reviewer of its own writing or reach the key it signs with; its ask reachable by somebody who cannot already write here, this repository being public and its reviewer spending a shared allowance; and machinery described on a page before a run has shown it working, which is the failure [#34](https://github.com/Adonis80/how-we-build/pull/34) closed on and [#38](https://github.com/Adonis80/how-we-build/pull/38) repeated.
