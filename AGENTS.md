Rulebook: this repository. A session reads `HOW-WE-BUILD.md`; this file exists for the reviewer of changes to the rulebook itself, because a reviewing tool loads only `AGENTS.md`. It is the brief for either reviewer — the badge, asked with `/claude review`, and Codex, asked with `@codex review` — and `.github/workflows/review.yml` reads it from protected `main`, never from the head under review, so a pull request cannot write its own reviewer's instructions.

# AGENTS.md — how-we-build

What is particular here: this repository is the rulebook, not a product. It changes only by pull request against protected `main`. Adding a rule, step, file, check or agent needs the charter's gate (§13) or the Chairman's own ruling; removing one, or correcting wording, needs neither. The proposer does not clear its own addition — the cold review does (§13). So the CTO may merge an addition of its own only on a commit a reviewer has read and left no finding on — never on one where it answered a finding, which would put the proposer back in the seat of the judge. Disagreeing with a finding is not clearance: the disagreement goes to the Chairman, who settles it. `check.sh` holds that rule rather than a hand: it is green only on a commit a reviewer has read and left nothing on, and red while the head carries a finding — the answer to a finding is a push, and the push makes a commit the reviewer reads afresh. The Chairman's hand is not the control and never was one — he approves by looking, not by reading a diff (his ruling, 14 September 2026). `check.sh` is the only check; `.github/workflows/review.yml` is a reviewer it waits for, not a second check. There is no `roadmap.json`: the queue here is the open pull requests — ready first, then by priority, then oldest (`README.md`, *Changing the rulebook*).

**Two reviewers, and one door between them.** Who they are is `DEFAULT_REVIEWER` and `GATE_REVIEWER` at the top of `review-gate.py`, and each answers one way only: Codex in prose the gate matches exactly, the default reviewer as a check run created by the `juku-reviewer` GitHub App — a login no branch can wear, a signal no writer can edit or erase. Its private key sits in the `reviewer` environment, which admits `main` alone, and `.github/workflows/door.yml` is the standing proof of that rather than the claim. The one class of the rulebook's cross-vendor list that can arise here is held in the gate rather than in prose: a pull request touching `check.sh`, `review-gate.py` or anything under `.github/workflows/` opens on Codex's clean read alone, whoever else has read it.

## Review guidelines
The brief is in `README.md`, *The independent reviewer*, and these lines repeat the least of it that the tool needs in front of it. Address the CTO. Form your view from the diff and the existing pages before the pull request's own account. With each finding say what you checked, what you did not, and how sure you are. Two rounds at most, then as the brief says. Prefer a deletion to another exception, and do not manufacture disagreement. Never write a file into this repository. Hazards particular here: an addition to how we build without the gate or the Chairman's ruling; the operating page over its word cap, or a shorter page that quietly requires less than the one it replaces; a file not on the list; two copies of one truth; provider-specific detail leaking into a global rule; a rule kept in prose that `check.sh` could hold; any claim that *build* is self-sufficient when a fresh session in either stack could not actually recover the work; a change to the review machinery cleared by the same vendor as the lead; the gate's register of reviewers and the wake job's condition drifting apart, so a read lands that nothing re-runs the check for; the reviewer workflow gaining any trigger beyond `issue_comment`, or losing its `environment: reviewer` line, either of which lets a branch run a reviewer of its own writing or reach the key it signs with; its ask reachable by somebody who cannot already write here, this repository being public and its reviewer spending a shared allowance; and machinery described on a page before a run has shown it working, which is the failure [#34](https://github.com/Adonis80/how-we-build/pull/34) closed on and [#38](https://github.com/Adonis80/how-we-build/pull/38) repeated.
